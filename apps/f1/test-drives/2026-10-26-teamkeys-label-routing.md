## Applicability and scenario

This changes runtime routing, so the F1 drive is required. A local configuration-only harness instantiated the real `EdgeWorker` in CLI mode, with the real F1 JSON-RPC issue tracker and native Codex runner. Production source was unmodified by the harness. It configured two active repositories in `cli-workspace`, both with `routingLabels: ["Design"]`. The first had `teamKeys: ["DEF"]`, the second `teamKeys: ["OTHER"]`. Each local fixture repository contained a different `ROUTING_ID.txt` marker.

A default-team issue, `DEF-1`, labeled `Design`, must select only the DEF repository. The bounded agent task read the selected repository's marker and returned it, without editing, committing, pushing or sending external messages. Codex used existing ChatGPT subscription authentication, no API key or paid API fallback. The CLI server bound only to `127.0.0.1:3617`.

## Limits

The fixtures used local Git repositories with no origin. GitService logged its local-main fallback after fetch failed; this did not make a network request. CLI issue-state metadata also logged a missing-team warning, while the actual webhook carried the DEF team key and the routing assertions passed. This drive validates CLI issue tracker, routing, worktree selection, Codex readback and activity output; it does not validate live Linear delivery or external Git operations. No runtime source changed beyond the existing PR's rebased patch.
