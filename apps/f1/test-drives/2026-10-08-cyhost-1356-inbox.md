# CYHOST-1356 inbox publication transport drive

Run: `pnpm build && bun apps/f1/inbox-publication-drive.mjs`.
Result: PASS on 2026-10-08.

Scenario: a Linear-enabled runtime MCP context publishes twice to one explicit
inbox, retaining the operation key, and an unauthenticated MCP caller is denied.
The drive constructs the actual EdgeWorker, registers its HTTP MCP endpoint,
creates context via McpConfigService, and connects the official SDK client. The
Linear SDK boundary is inert; no tracker request or model run is started. The
local Hosted receipt endpoint is a fixture using a synthetic runtime key.

Assertions passed:

- Actual runtime catalog contains `post_message_to_codex`.
- Runtime context and bearer authentication admit the SDK client.
- Both tool calls POST to `/api/codex-inbox/messages` using runtime credentials.
- Both payloads preserve inbox, text and idempotency key exactly.
- Returned receipt is `queued`, with the backend message ID.
- Unauthenticated MCP request receives 401.

The paired Hosted PostgreSQL/HTTP integration suite checks destination/team
isolation, durable storage, verification, delivery retries and revocation. This
F1 drive does not establish a dot/Cloud Work OAuth connection, native local
Codex listening, or receiving model execution. Those remain separate live
acceptance work after an authorized deployment and intentional user subscription.
